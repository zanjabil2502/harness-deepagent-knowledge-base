Invoke the `agent-harness-kb` skill, then run its **weighing** mode for:
$ARGUMENTS

Its route is deliberately *not* the diagnostic procedure:

1. Start from the **6 discriminating axes** in `SKILL.md` as a menu of
   choices, not a form to complete. Ask only what the idea leaves genuinely
   ambiguous.
2. Check `references/systems/INDEX.md` for systems that already do something
   like this, and read the relevant T2 file's distinguishing character before
   claiming novelty.
3. Read the `## Problem` and `## Trade-offs` sections of the concepts the idea
   actually touches - not every concept. In archetype files read
   `## Example systems` and `## Common pitfalls`.

In this mode the explanation **is** the output. Stopping without a blueprint
is legitimate and often correct. State what was traded for what, and name the
decisions that are still open rather than closing them silently.
